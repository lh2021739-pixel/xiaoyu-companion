# 共享记忆格式 v1（11.21）

一句话：故事和机器人往同一个"记忆服务"里**写事件**；各自开口前，**取一段给自己看的上下文**。
记忆服务跑在演示用的 Mac 上：本机 HTTP 服务，端口 8900，数据存两个文件。

## 一、存什么：两种东西

### 1. 事件（只追加、不修改）——文件 `events.jsonl`，一行一条
每发生一件值得记的事，就写一条。

```json
{
  "id": "evt_20261121_201503_a1",
  "user_id": "demo",
  "time": "2026-11-21T20:15:03+08:00",
  "source": "story",
  "type": "choice",
  "summary": "在故事里，主人答应了周末陪小屿去看海。",
  "detail": {"choice": "陪你去看海", "chapter": 3},
  "emotion": null,
  "importance": 2
}
```

| 字段 | 说明 |
|---|---|
| `source` | 从哪来：`story`（网页故事）或 `robot`（桌上机器人） |
| `type` | `choice` 故事里的选择；`story_event` 故事里发生的大事；`said` 用户对机器人说的事；`emotion` 用户的情绪时刻 |
| `summary` | **最关键**：一句话，第三人称，写给"另一边"看的。另一边直接把这句话放进提示词 |
| `detail` | 原始信息（选项原文、用户原话等），只作为备查，不放进提示词 |
| `emotion` | 情绪时刻才填：`{"label": "开心/难过/生气/累/平静", "evidence": "语气标签SAD；原话'好累'"}` |
| `importance` | 1 一般，2 重要，3 很重要（承诺、重大情绪）。上下文放不下时，先保留分数高的 |

### 2. 画像（会更新）——文件 `profile.json`
从事件里提炼出的长期信息。每次一场聊天结束或一章故事结束，更新一次。

```json
{
  "user_id": "demo",
  "user": {
    "call_name": "主人",
    "facts": [{"text": "在公司做方案，最近压力大", "source": "robot", "time": "..."}],
    "likes": [{"text": "喜欢喝热可可", "source": "robot", "time": "..."}]
  },
  "promises": [
    {"text": "周末一起去看海", "source": "story", "time": "...", "status": "未兑现"}
  ],
  "relationship": "刚认识两天，开始信任小屿"
}
```

`promises`（约定）单独列出来：两边都会反复提起，最能体现"它记得我"。

## 二、怎么写（谁在什么时候写）
- **故事平台**：玩家每做一次选择，写一条 `choice`；每章结束时，挑出这一章的大事，写一条 `story_event`。
- **机器人**：每轮对话，大模型都会顺带输出 `remember`（要记住的事）和情绪。有内容才写，写成 `said` 或 `emotion`。情绪判断要结合 SenseVoice 的语气标签和原话。
- **画像**：一场聊天结束、或一章故事结束时，调一次大模型，把新事件合进 `profile.json`。

## 三、怎么读（开口前取上下文）
记忆服务替每一边记着一个"已读到哪"的位置。每次 `GET /context` 只返回**对方那边的新事件**，返回后自动标为已读（不需要调用方再确认），这样同一件事不会被反复提起。

| 接口 | 谁调用 | 返回 |
|---|---|---|
| `POST /events` | 两边 | 写一条事件 |
| `GET /context?for=robot` | 机器人每场聊天开始前 | 故事里的新事件 + 画像 + 最近的情绪时刻，已经拼成一段提示词文本 |
| `GET /context?for=story` | 故事每章生成前 | 机器人那边的新事件 + 画像，已经拼成"现实中刚发生的事"文本 |
| `GET /all` | 演示大屏 | 全部事件和画像（给评委看"它记住了什么"） |

返回的文本示例（`for=story`）：
```
【现实中刚发生的事 · 来自玩家桌上的陪伴机器人（同一个角色的记忆）】
- 今天主人在公司被老板当众批评了，回家时很累、很低落。（情绪：难过）
- 主人说他喜欢喝热可可。
【一直记得的】
- 约定：周末一起去看海（未兑现）
本场要让相关角色自然地记得并回应这些事（先回应玩家的情绪），不要生硬复述。
```
这段文本的放法已经实测有效：放在提示词里"上一章发生了什么"之后。放进世界观设定，模型会忽略它。

## 四、"最新信息"和"提前生成"怎么兼顾
不在聊天之前提前生成，而是**聊完马上生成**：机器人这场聊天一结束，记忆写进去，就立刻在后台生成下一章。用户从机器人走回网页的那几十秒里，这一章已经在写了。故事平台本身是边写边显示的，所以不用干等整章写完。

## 五、约定
- 一个演示用户 `user_id = "demo"`。每个用户的数据单独存放，这是路演时讲"数据隔离"的依据。
- 时间统一用北京时间的 ISO 格式。
- `summary` 一律用"主人"称呼用户，用"小屿"称呼角色，角色名定下来后统一替换。
