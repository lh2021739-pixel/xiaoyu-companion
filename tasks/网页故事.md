# 任务卡：网页故事（故事同学）

## 做什么
在你现有的无限故事平台上，加上"翻记忆本"和"写记忆本"两个动作。

角色设定：陪伴机器人"小屿"，温柔、好奇；玩家被称作"主人"；讲两人的日常，温暖治愈；每章结尾给 2 到 3 个选项。

## 要改三处
1. **玩家选完选项时**：写一次记忆本，记下玩家选了什么。
2. **生成下一章之前**：翻一次记忆本，把拿到的 `text` 放进提示词里。
   - 要放在"上一章玩家选了什么"的**后面**。**不要**放进世界观设定，放在那里模型会忽略它，我们测过。
3. **模型配置**：从环境变量读取 `base_url`、`api_key`、`model`，接口要兼容 OpenAI。

记忆本连不上时，故事照常能玩，只是不带记忆。

## 记忆本还没好，怎么开发
真正的记忆来自机器人对话。机器人接上之前，先用**假记忆本** [tools/mock_memory_server.py](../tools/mock_memory_server.py)：
```
python3 tools/mock_memory_server.py
```
它只依赖 Python，不需要机器人。启动时已经写好一条"机器人刚聊过的事"：**今天主人在公司被老板当众批评了**。你的故事读到它，就该在下一章里安慰主人。

想换一件事试，就"假装机器人又聊了一句"：
```
curl -X POST http://127.0.0.1:8900/events -d '{"source":"robot","type":"said","summary":"主人说他喜欢喝热可可。"}'
```
最后联调时，把假记忆本换成真的。接口完全一样，你的代码不用改。

## 两个接口（地址 `http://127.0.0.1:8900`）
**写记忆本**
```
POST /events
{"source":"story","type":"choice","summary":"在故事里，主人答应了周末陪小屿去看海。"}
```
`summary` 写成一句话、用第三人称，说清玩家选了什么。

**翻记忆本**
```
GET /context?for=story
→ {"has_new": true, "text": "【现实中刚发生的事】\n- 今天主人在公司被老板当众批评了……\n【一直记得的】\n- 约定：周末一起去看海\n请让小屿先回应主人的情绪，并自然提起这些事。"}
```
同一件事只会给一次，读过一次就不会再重复给。

## 怎么算做完
1. 开着假记忆本生成下一章时，小屿要**先安慰主人**，再**自然地提到去看海**。
2. 选一个选项后，假记忆本的窗口里打印出"收到事件"，并且 `summary` 内容正确。
3. 在 Mac（Apple 芯片）上，一条命令能装好，一条命令能启动。
